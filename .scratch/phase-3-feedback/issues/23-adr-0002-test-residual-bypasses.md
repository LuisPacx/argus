**Status:** ready-for-agent (once 18 has merged)

**Bypass (a), medium: non-literal scheme.** `URL_RE` and `DYNAMIC_HOST` both start from a literal `http(s)://` or `ws(s)://`. A URL whose scheme is not literal never matches them: `` `${scheme}://api.helius.xyz/` ``, a protocol-relative `"//api.helius.xyz/"`, or string assembly like `"ht" + "tps://..."` (the concatenation case where the host is a separate literal). Fix: add a scan for bare banned hostnames. For every file (the read-only module included), look for a banned host as a standalone token in the text, whatever precedes it, and apply the same allowances as for URLs (the pinned `mainnet.helius-rpc.com` in `helius.ts` only; `pumpportal.fun` data stream and `pump.fun/coin/` links as allowed today). Reuse `BANNED_HOSTS` and `stripTrailingDots`; do not keep a second host list. Decide and record in Comments how bare hostnames in comments, docs and fixtures are handled (the scan already reads text, so a hostname in a comment of a non-exempt file would be flagged; prefer a narrow, reviewed exemption list over weakening the scan, and keep the list frozen like `DYNAMIC_HOST_FILES`).

**Bypass (b), low: userinfo via the loopback exemption.** `DYNAMIC_HOST` exempts `(localhost|127.0.0.1):${`, meant for test servers on a port variable. `http://127.0.0.1:${p}@api.helius.xyz/` passes the exemption, and a real URL parser reads `127.0.0.1:<p>` as userinfo and `api.helius.xyz` as the host. Fix: after the interpolation's closing `}`, require `/`, `?`, `#`, a quote or backtick, or the end of the literal; anything else (`@`, `.`, a letter, another `${`) is not exempt. Check the same for `localhost:${p}` and for a template with more than one interpolation.

## Comments
**Built (test-only, `packages/core/src/adr-0002.test.ts`).** (a) `bareHostViolations` scans the text for any `BANNED_HOSTS` hostname (or `host:port`) whatever precedes it, after `normalizeForHosts` (JS `\x`/`\u` escapes, HTML entities, `%xx`, NFKC, ideographic stop, zero-width characters, `\.`, line continuations) and on three views of the text: as is, adjacent literals joined (`"a" + "b"`, `["a", "b"]`, `.concat`, `${"a"}`, block comments dropped), and array elements joined with `.`. Same allowances as for URLs: `pumpportal.fun/api/data`, `pump.fun/coin/`, and the pinned `mainnet.helius-rpc.com` in `helius.ts` only (as a plain token or after a literal `https://`; not after `//`, `${s}://`, `@`, with a port, trailing dot or a path other than `/` or a query). No dot segment, backslash or empty segment rides an allowed prefix. A host already reported as an `endpoint` is not reported twice. `DYNAMIC_HOST` now also covers a missing or built scheme (`}://`, `"//"`, `"://"`); the module also bans a bare `"//"` or `"://"` literal. A `:8899`/`:8900` port is flagged even when the host is built elsewhere (`${h}:8899`). (b) The loopback exemption requires the closing `}` of the port interpolation to be followed by `/ ? #`, whitespace, a quote, `)`, `<`, `>` or the end; `@`, `.`, a letter, `\` or another `${` is not exempt.

**Evasions tried against the new checks and closed:** uppercase; trailing dots; `%2e` and `%69`-style encoding; `\x`, `\u`, `\u{}` and HTML numeric/`&period;` escapes; full-width forms and the ideographic stop; zero-width characters; `\.` and a backslash-newline inside a literal; userinfo and port variants; a host split across literals, lines, `.concat`, array `.join("")` or `.join(".")`, `${"..."}`, or a block comment; `${scheme}://${host}`; `"//" + host`; `scheme + "://" + host`; a banned host in a query or path of another URL; `pump.fun/coin/../api/trade`; a second interpolation, `@` or `.` after the loopback port variable.

**Residual, not closed** (also listed in the test header): a host or URL read from a file, the network, config or a lookup table; base64 and other run-time decoding (`atob`, `Buffer.from`, `.reverse()`, `.replace()`); a host assembled from a variable between literals (`"api." + vendor + ".xyz"`); legacy octal escapes (`\150`); a line comment between joined literals; an IP address or CNAME of a banned host; a local validator spelled non-canonically (`[::ffff:127.0.0.1]`, `0.0.0.0`) or on another port; a loopback port variable that holds `8899` at run time (the exemption is meant for test servers); a bare `pump.fun` in a frozen file followed later by a path assembled elsewhere (`["https", "pump.fun"].join("://")` then `+ "/api/trade"`); files that are not scanned (JSON, Markdown, config); an interpolation whose own text is a string with userinfo (`` `http://127.0.0.1:${"@x"}/` ``) when `x` is not a banned host.

**Review round 1 (security review of b8327a6), fixed in the follow-up commit.**
1. The loopback exemption accepted any whitespace after the port's `}`; a URL parser strips CR, LF and TAB, so `` `http://127.0.0.1:${p}<LF>@${h}/` `` had host `h`. Now only a literal space (or `/ ? #`, a quote, `)`, `<`, `>`, the end) is accepted. Tests use a real LF, CR, TAB, CRLF.
2. `BARE_APEX_FILES` is asserted as the exact six-file list (no spare slot), besides the exists check.
3. Closed: identity escapes (`'api.hel\ius.xyz'`), nested templates (`` api.heli${`us`}.xyz ``, `${"he" + "lius"}`, a few levels deep), bracket-call concat (`'a'['concat']('b')`), `\u{...}` and `&#x...;` / `&#...;` with any number of leading zeros. Still residual: legacy octal escapes, a line comment between joined literals, chaining after a closing quote (`` `http://127.0.0.1:${p}` + "@" + h ``), hosts assembled from variables, the `:8899|8900` port rule (a port variable that holds it at run time).
4. One sentence-ending period after the pinned host is now fine in prose (`// Calls mainnet.helius-rpc.com. Read-only.`, `/** POST to https://mainnet.helius-rpc.com/. */`): only when followed by whitespace or the end of the text and not preceded by `/`, `@` or a quote; a dot inside a URL or string (`"mainnet.helius-rpc.com."`, `https://mainnet.helius-rpc.com./`, `//host. `, `host.:8899`, `host./v0/send`, `host..`) is still flagged, in tests on both sides. The same rule applies to the apex-name prose in the frozen files, so `"pump.fun."` as a string is now flagged there.
5. No exemption for prose or test files. Rule for the next implementer (also in the test header): helius.ts may spell the pinned host (plain token or a literal `https://` URL); tests of that module must import a whole endpoint constant exported from helius.ts (`export const HELIUS_RPC_URL = "https://mainnet.helius-rpc.com/"`) instead of spelling the host; comments and fixtures must not name any other banned host. The scan does not ban that import (only chain, wallet and key packages). Caveat: rebuilding a URL from a host constant in a test (`https://${HOST}/`, `"https://" + HOST`) is "a host built at run time" and needs a reviewer-approved DYNAMIC_HOST_FILES entry, so import the full URL.
6. `joinLiterals` strips block comments in one linear pass (the lazy regex took 19 s on 50k unclosed `/*`; a test now bounds three such inputs under 3 s). The redundant `|| violations(...).length > 0` disjunct in the frozen-list test is gone.
