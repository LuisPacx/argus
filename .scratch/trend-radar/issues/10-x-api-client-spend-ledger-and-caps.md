# 10: The X API client: one host, a spend ledger, caps in code, a dry run
**Model:** sonnet / high. A key, real dollars and a spend cap. A mistake here costs money silently, or leaks a credential.

**What to build:** the client that every stage B ticket goes through, and nothing that calls it yet. One module names the X API host and exactly two read endpoints (Trends by place, Counts recent). Every request first passes the spend gate: a ledger of what was spent in the rolling 24 hours and 30 days, a daily cap of $3.00 and a 30-day cap of $90 in code, a dry run that sends nothing, fail-closed rules for unknown cost and an unreadable ledger. The key comes from `.env` through the dev server's one new allowed name. Useful alone: the spend cap and its page block exist and are tested before a single paid request is made, so tickets 11 and 12 cannot spend without them.

**Status:** blocked (waits for the Operator's step, ticket 09)

**Blocked by:** 01, 09
Spec: section 4.2 and 7. ADR 0016 decision 3. Pattern: `packages/core/src/study/helius.ts` (the one module that names a host and its verbs, with its cost table), `api-spend.test.ts` and `MAX_API_DAILY_USD` for the cap style, `scripts/dev-env.mjs` for the allowed `.env` names.

## Evidence and design (read before building)

- **Verify first, then build.** The research read these pages on 2026-11-19 and the agent re-reads them now: https://docs.x.com/x-api/getting-started/pricing (Trends $0.010 a request, Counts recent $0.005 a request, pay-per-use), https://docs.x.com/x-api/trends/introduction (`trend_name`, `tweet_count`, the place parameter and its ids for worldwide, US and UK), https://docs.x.com/x-api/fundamentals/rate-limits (75 requests per 15 minutes per app for Trends). Also settle from the docs, and write the answers in Comments: the exact paths and parameters, the Counts granularity (hourly buckets, as the research recalls and marked inferred), whether a Counts re-read is billed again, whether a response reports its own usage or cost, and how an exhausted prepaid balance is signalled (the status code and body). **If a price or an endpoint differs from this ticket, stop and tell the Operator before writing code.**
- **One module, one host, two verbs.** `packages/core/src/radar/x-api.ts` names the host once (https, no userinfo, no port, a constant) and exports `getTrends(woeid)` and `getCountsRecent(query)` only; no generic `request(path)` is exported. `adr-0002.test.ts` bans swap and RPC hosts, not this host, and stays unchanged; add `x-api-host.test.ts`, a tripwire in the same spirit: only that module may name the host, only these two paths exist, and no other file spells either.
- **The key.** `X_API_BEARER_TOKEN`, read by `radar/x-api.ts` from the worker's environment only when `ARGUS_RADAR_X_API=1`; `scripts/dev-env.mjs` gains the exact name in `EXTRA_KEYS` (the Operator approved it in ticket 09, step 7; if he chose another name, use that one) and its test is updated; the key is kept in a private field, never logged, never put in an error (errors are rebuilt from the status alone, the way `api-brain.ts` does), never passed to a child process, deleted from the worker's environment after it is read. A request in a log line or a stored run shows the path and the status, never a header.
- **The spend gate** (`radar/x-spend.ts`, table `x_api_spend`: time, endpoint, units, price, status, dry-run flag). Before every request: the sum of the rolling 24 hours plus the price of this request must not pass `X_API_DAILY_USD_CAP` ($3.00 constant) and the rolling 30 days must not pass `X_API_MONTHLY_USD_CAP` ($90 constant); otherwise the request is **not sent**, the call returns `capped` and the page says which cap. `ARGUS_RADAR_X_DAILY_USD` and `ARGUS_RADAR_X_MONTHLY_USD` can only lower; a value above the constant, zero, negative or not a number is an error at startup (invariant 3). Prices are constants with their source and the date read in a comment (`$0.010` and `$0.005`); a response that carries its own cost, if the docs say it does, is checked against them and a mismatch pauses the client.
- **Fail closed.** A request of unknown cost (timeout, cut connection, 5xx, an answer with no readable status) is charged at its price. A ledger that cannot be read or written counts as spent. The request is written to the ledger **before** it is sent and updated after, so a crash leaves the charge standing.
- **Failure handling** (spec 4.2): 429: wait for the reset header and send nothing more this tick; 401, 402 or 403 (a bad token or an exhausted prepaid balance): stop the client for the rest of the UTC day, show it on the page, tell the Operator through the notice path the moment scanner's stop uses; 5xx: one retry on the next tick; a body that is not the documented shape is `format changed`, never an empty result.
- **Dry run.** `--dry-run` and `ARGUS_RADAR_X_API_DRY=1` log `[x-api] dry-run: GET <path> price=$0.010` and send nothing, record nothing as spent, and need no key.
- **Page block.** `/radar` shows the X API state: off, dry, on, stopped (with the reason), today's and 30-day dollars against the caps, requests by endpoint. Read-only `GET /api/radar` field.

## Acceptance criteria

- [ ] **Spend gate** (`x-spend.test.ts`, fake clock, real Datastore on a temp dir): requests are sent until the next would pass $3.00 in the rolling 24 hours and that one is `capped` and unsent (2 Trends at $0.010 and the rest Counts reach the cap exactly as computed by hand); the 30-day cap of $90 holds across days; old spend ages out; an unknown-cost failure is charged at its price; a ledger that cannot be written sends nothing; a crash between write and send leaves the charge standing.
- [ ] **Caps cannot be raised** (`x-spend.test.ts`, `startup-config.test.ts`): `ARGUS_RADAR_X_DAILY_USD=10` and `=0` and `=abc` are startup errors; `=1` lowers the cap to $1.
- [ ] **Client** (`x-api.test.ts`, fake fetch with recorded response fixtures, one per endpoint): the documented shapes parse (`trend_name` and `tweet_count` with a missing count for a trend under 1,000; hourly count buckets); a body in another shape is `format changed` and not an empty list; 429 honours the reset header; 401, 402 and 403 stop the day; 5xx retries once next tick; a response body or error never contains the token (a test passes a token string through every error path and greps the output).
- [ ] **Host tripwire** (`x-api-host.test.ts`): only `radar/x-api.ts` names the host; only the two paths exist; no generic request function is exported; `adr-0002.test.ts` passes unchanged.
- [ ] **Key handling** (`x-api-key.test.ts`, `scripts/dev-env.test.ts`): the key is read only when `ARGUS_RADAR_X_API=1`, is absent from `process.env` afterwards and from every child's environment, is never in a log line; `dev-env.mjs` passes the exact approved name and no other non-`ARGUS_` name; the start's `env:` line lists names only.
- [ ] **Dry run** (`x-api.test.ts`): sends nothing, records nothing as spent, needs no key.
- [ ] **Page block** (`radar-render.test.ts`, `pnpm page:check --seed /radar`, seeded; add X API states to the seed): each state, the two caps and dollars, the reason when stopped; no overflow at 390 or 1240 px.
- [ ] Type-check, `pnpm lint` and the full `pnpm check` pass, run once before the commit.
