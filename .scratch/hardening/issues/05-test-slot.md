# 05: Machine-wide test slot (at most two full suites at once)
**Model:** sonnet / medium — small script, but process-liveness and locking are easy to get subtly wrong.

**What to build:** the rule "at most two full suites run on this machine at once" (`docs/agents/worker-rules.md`), across all git worktrees and all agents, is enforced by the tooling instead of by each brief. Today agents guess with `pgrep` patterns that misfire: vitest spawns worker processes, so a pattern like `node.*vitest` counts one suite as several, and patterns also match bash shells and the `pgrep` itself. On 2026-11-11 this stalled workers several times (one waited about 25 minutes for a slot that was actually free).

Shape (check against `scripts/check.mjs` and `package.json`; the code agrees with it today: `pnpm check` is `node scripts/check.mjs`, which runs `typecheck`, `lint`, `test` in sequence with `spawnSync`, so one slot taken at the top of `check.mjs` covers all three steps):

1. **`scripts/test-slot.mjs`**, a small module plus CLI. There are `SLOTS = 2` slot files, e.g. `slot-0.json` and `slot-1.json`, in a directory on the home disk shared by every worktree: `${XDG_STATE_HOME:-~/.local/state}/argus/test-slots/` (override with `ARGUS_TEST_SLOT_DIR` for tests). Never `/tmp` and never inside a worktree. Taking a slot is an atomic create (`open` with `wx`) of a slot file holding `{ pid, startTime, worktree, command, since }`. A slot is stale, and may be reclaimed, when its holder `pid` is dead or its process start time no longer matches (PID reuse); check with `process.kill(pid, 0)` plus the start time from `/proc/<pid>/stat`, and say in Comments how the Linux-only start time is handled elsewhere. Release removes the file.
2. **`pnpm check` takes a slot.** `scripts/check.mjs` (both the full run and `--fast`? see scope) acquires a slot before the first step and releases it in a `finally`, on `process.exit` paths, and on SIGINT/SIGTERM. If both slots are held by live processes it prints a visible line such as `check: waiting for a test slot (2 of 2 held: <worktree> pid N since HH:MM, ...)`, re-printing at a modest interval, and polls; after a timeout (default 45 minutes, `ARGUS_TEST_SLOT_TIMEOUT_MS`) it exits non-zero saying who holds the slots. A crash or `kill -9` of the holder frees the slot through the stale-holder check, with no cleanup step needed.
3. **`node scripts/test-slot.mjs status`** for humans and briefs: prints each slot as free or held (pid, worktree, command, age), and exits 0 when at least one slot is free, 1 when both are held (so a brief can use it as a check). `node scripts/test-slot.mjs wait` blocks until a slot is free without taking it, for the rare case something outside `pnpm check` needs it.
4. **`docs/agents/worker-rules.md`** gets one line replacing the guessing: `pnpm check` takes one of two machine-wide test slots itself and waits when both are taken; `node scripts/test-slot.mjs status` shows who holds them; never count processes with `pgrep`.

**Status:** ready-for-agent

**In scope:** the full `pnpm check`. `pnpm check:fast` also takes a slot only if the measured load of the fast tier justifies it; default is that it does not (it is the ~1-2 minute iteration tier), and the choice is recorded in Comments.
**Out of scope:** stress loops (these already follow the one-loop, `--maxWorkers=2` rule in the Operator's global instructions and are not `pnpm check`); single-file or `pnpm test:fast` vitest runs; a bare `pnpm typecheck`, `pnpm lint` or `pnpm test` run directly (they bypass the slot, and the worker rule still says to use `pnpm check`); limiting the slot count by CPU or memory; non-Linux machines beyond not crashing.

- [x] `scripts/test-slot.mjs` exports acquire, release and status helpers and has the `status` and `wait` commands; slot state lives under the home-disk directory above, shared by all worktrees, never `/tmp`
- [x] `scripts/check.mjs` takes a slot before its first step and releases it on success, on a failing step, on SIGINT/SIGTERM and on an uncaught error
- [x] When both slots are held, `pnpm check` prints a "waiting for a test slot" line naming the holders, keeps waiting, and proceeds when one frees; it times out with a non-zero exit and a message naming the holders
- [x] Stale holders are reclaimed: a slot file whose pid is dead, or whose pid is alive but has a different start time, does not count as held (tested)
- [x] A third concurrent acquirer does not get a slot while two live holders exist, and two acquirers racing for the last slot cannot both win (tested with the slot directory and a short timeout overridden through env, with real child processes or injected liveness checks; no real suite is run)
- [x] `status` output and exit code are correct for 0, 1 and 2 held slots (tested)
- [x] Tests sit beside the script as `scripts/test-slot.test.ts`, like the other `scripts/*.test.ts`; temp dirs go through `packages/core/src/testing/temp.ts` and are removed; the file is in exactly one tier (`scripts/test-tiers.test.ts` guards it)
- [x] `docs/agents/worker-rules.md` has the one new line, and the existing "At most two full suites run on this machine at once" sentence points at it

## Comments

- Slot module: `scripts/test-slot.mjs` (API: `slotDir`, `readStartTime`, `status`, `formatStatus`, `tryAcquire`, `acquire`, `waitForFree`, `holdSlot`). `holdSlot` = acquire + release on `exit` (covers `process.exit`, uncaught errors), SIGINT, SIGTERM, SIGHUP.
- Stale holders: dead pid (`process.kill(pid,0)`, EPERM counts as alive) or a `/proc/<pid>/stat` start time (field 22) that differs from the recorded one. Start time is Linux-only; elsewhere it is null and a null on either side skips that comparison, so only the pid check applies (no crash, PID reuse undetected). A crashed or `kill -9` holder frees its slot by itself. Tests plant slot files with a dead pid (a child that already exited) and with our own live pid plus a wrong start time, so nothing depends on timing.
- An unparseable slot file (creator crashed between create and write) counts as held for 5 s, then stale, so a reader never mistakes a half-written live file for a free slot.
- Races: all acquire attempts run under a `mkdir` lock (`lock` dir in the slot dir, broken if older than 10 s), so two reclaimers of one stale slot cannot delete each other's fresh file; the `wx` create stays as a second guard. Release only deletes the file if it still names our pid. Tested in-process and with four real racing child processes (`scripts/test-slot-holder.fixture.mjs`).
- `check.mjs` now spawns steps asynchronously (was `spawnSync`): a blocking `spawnSync` never lets a SIGTERM handler run, so the slot could not be released on a signal. On a signal the current step child is sent SIGTERM and the process exits 128+n. The git snapshot for stamping is now taken after the wait, so the stamp describes the tree the steps ran on.
- `pnpm check:fast` does not take a slot (default from the ticket; not measured). Only the full run does.
- Wait line: `check: waiting for a test slot (2 of 2 held: <worktree> pid N since HH:MM, ...)`, printed at once and every 30 s; timeout (`ARGUS_TEST_SLOT_TIMEOUT_MS`, default 45 min) rejects with `timed out ... (holders)` and `check` exits 1.
- Tests: the waiting line, proceed-when-freed and timeout are tested on the module (injected `sleep`, short timeout), not by running `check.mjs`; the full `pnpm check` run before the commit exercises the `check.mjs` path. Tests use `tempDir` and pass the dir explicitly, never the real slot dir. The file stays in the fast tier: its child processes are one-line node scripts that finish in well under a second.
- Review fix (signals): steps now start through `spawnStep` as their own process group (`detached: true`), and a signal runs `killTree`: signal the whole group (`process.kill(-pid, sig)`), poll until no process of the group is left, SIGKILL the group after a 5 s grace (`graceMs`), give up after 5 s more. `holdSlot` awaits `onSignal` before releasing and exiting 128+n, so the slot is held until the step group is gone (pnpm does not forward signals; vitest/tsc are grandchildren). Bounds: a process that left the group (setsid/setpgid) is neither signalled nor awaited, and a group that still has members 5 s after SIGKILL no longer holds the slot (released anyway). A detached group no longer gets the terminal Ctrl-C, so the handler forwards SIGINT/SIGTERM/SIGHUP itself. Exit codes, step order, stdio passthrough (`stdio: inherit`) and the stamp are unchanged. After a signal the main loop parks (`stopping`) so a step closing cannot exit first with its own code. `check:fast` runs its steps as a group too and forwards signals, but holds no slot.
- Tests for it use a real tree (parent fixture -> mid -> grandchild, `scripts/test-slot-holder.fixture.mjs`): after the signal the grandchild must be dead, and a poll (slot read before the grandchild's exit marker) proves the slot never vanishes while the slow-to-stop grandchild still runs; a SIGTERM-ignoring grandchild proves the SIGKILL fallback. The tests wait for the grandchild's ready file (handler installed) rather than sleeping, and in `afterEach` kill the parent, then the step's whole process group (the fixture records the step leader's pid in `mid.pid`) and the grandchild pid, from whatever pid files exist. Narrow gap: a parent SIGKILLed between spawning the step and writing `mid.pid` leaves that step. With `killTree` mutated back to `child.kill(signal)` all three fail.
- Unusable slot directory (cannot be created or written): decision is to keep failing, never to run without a slot. `check` exits 1 for every run until fixed, with the message `test-slot: cannot use the slot directory <dir> (<code>); make it writable or set ARGUS_TEST_SLOT_DIR to a writable directory`. Running unslotted would silently break the two-suite limit this ticket exists to enforce, and a visible hard error is cheap to fix. Tested.
