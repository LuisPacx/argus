# 16: War Room Activity page
**Model:** sonnet / medium — one read-only page, three small routes, two additive datastore columns/tables.

**What to build:** A read-only `/activity` page in the War Room (`apps/warroom`) so the Operator can watch the pipeline live without reading worker logs: per-Source health, the newest Narratives with their latest Score and gate result, recent Brain runs (judge and propose), and today's research usage against its budget and the Proposal daily cap. No buttons, no commands, no writes from the War Room. The page refreshes on the client only.

**Blocked by:** the War Room SSR fix for `apps/warroom/app/pages/index.vue` (a `setInterval` created at setup crashes SSR). Do not start before it is on main; this page must not repeat the bug.

**Status:** done

## What exists today (mapped)

War Room (Nuxt, `apps/warroom`): pages `index.vue` (Proposals), `proposals/[id].vue`, `narratives/index.vue`, `narratives/[id].vue`, `rubric.vue`; routes under `server/api/` (`signals.get`, `research.get`, `narratives/index.get`, `narratives/[id].get`, `proposals/**`, `rubric.*`, `commands.get`). Every route reads through `useStore()` (`server/utils/db.ts`), a `WarRoomStore` = a narrow `Pick<Datastore, ...>` of `@argus/core` over the same SQLite file the worker writes. A new read the page needs is a new method added to that `Pick`, never a raw SQL call in a route. Route tests live in `apps/warroom/server/test/` and call the real handler with Nitro globals stubbed over `Datastore.open(":memory:")` (see `research.test.ts`).

## Smallest datastore additions (additive, idempotent, in `migrate()`)

1. `source_polls` table, one row per Source, upserted by `ingestSources` after every poll: `source_id TEXT PRIMARY KEY, source_label TEXT, last_polled_at TEXT NOT NULL, last_ok_at TEXT, last_error TEXT, last_error_at TEXT`. A success sets `last_ok_at` and clears `last_error`; a failure keeps `last_ok_at` and sets the error message (truncated to 300 chars, no URLs with tokens/query strings). This gives "last fetch", "last error", and lists a Source that has never produced a Signal. Write it through a worker-only method (like `touchBrainRun`); `WarRoomStore` gets only the read method. `ingestSources` takes `Pick<Datastore, "recordSignals" | "recordSourcePoll">`.
2. `brain_runs.finished_at TEXT` (nullable), set by `finishBrainRun` (and the interrupt/stale sweeps, which end runs too). Duration = `finished_at - created_at`; an `in-flight` row shows elapsed so far. Rows from before the column have null `finished_at` and show duration as unknown (no backfill).

Nothing else is added. Do NOT add per-Source "items in 24 h" or gate result columns: both are derived at read time.

## Acceptance criteria

Every AC lists endpoint tests (in `apps/warroom/server/test/activity.test.ts`) that call the real handler against `Datastore.open(":memory:")` and assert the full response shape with `toEqual`/`toMatchObject`, not just status or key presence.

- [x] **Source health.** `GET /api/activity/sources` returns an array, one object per Source in `source_polls` plus any Source that has Signals but no poll row (legacy, `lastPolledAt: null`), sorted by `sourceId`: `{ sourceId, label, lastPolledAt, lastOkAt, lastError, lastErrorAt, signals24h }`. `signals24h` counts `signals.ingested_at` in the rolling 24 h, `lastError` is null after a later success. `ingestSources` records a success, a failure (message kept, `lastOkAt` unchanged) and a Source that returns zero items (polled, ok, `signals24h: 0`). Tests: a Source that fails then succeeds; one that fails after succeeding keeps `lastOkAt`; a Signal ingested 25 h ago is not counted; two Sources each get their own row; an `ingest.ts` test that one failing Source still records the others.
- [x] **Narratives.** `GET /api/activity/narratives` returns the newest 20 Narratives by `createdAt` descending (ties by id descending): `{ id, title, signalCount, createdAt, lastSignalAt, score: { total, rubricVersion, createdAt, scores } | null, gate: { dimension: "buildability", value, min, passed } | null }`. `gate` and `score` are null for an unjudged Narrative; `min` comes from the Rubric version the Score used, not the current one. Tests: unjudged (both null); judged and passing; judged and failing the gate at its own version while the current Rubric would pass it (proves the version lookup); a Narrative with two Scores shows the latest; ordering and the 20 limit.
- [x] **Brain runs.** `GET /api/activity/brain-runs` returns the newest 20 runs with `task` in `judge` or `propose` (Spec and Build runs excluded), id descending: `{ id, task, status, backend, model, narrativeId, proposalId, estCostUsd, startedAt, finishedAt, durationSec }`. `status` is the `exit_status` (`in-flight`, `interrupted`, `success`, ...). `durationSec` is `finished_at - created_at` rounded to whole seconds; for `in-flight` it is `null` and `finishedAt` is null (the page shows elapsed from `startedAt`); a pre-column finished row has `durationSec: null`. `estCostUsd` is `total_cost_usd`, labeled "est." in the UI for claude-code runs; an API-backend run's dollars are real and the route marks it with `costKind: "est" | "api"` taken from `backend`. Tests: finished run duration; in-flight run; interrupted run; pre-migration row; spec/build runs excluded; API-backend run marked `api`; `finishBrainRun` and the stale sweep both set `finished_at`.
- [x] **Usage and cap.** The page reads the existing `GET /api/research` for `usedUsd` vs `budgetUsd` (= `ARGUS_DAILY_QUOTA_USD` x `ARGUS_RESEARCH_SHARE`) and `newProposals` vs `newProposalsCap` (10). No new route and no copy of its logic. Extend `research.test.ts` only if the shape changes; add a test that with `ARGUS_DAILY_QUOTA_USD=10`, `ARGUS_RESEARCH_SHARE=0.5` and 11 `propose`/`judge` dollars of runs the response has `budgetUsd: 5`, `exhausted: true`, and that `newProposalsCap` never exceeds 10.
- [x] **Page.** `app/pages/activity.vue` (linked from the app header) renders the four sections from the routes above using the existing Nuxt UI components and the `narratives/index.vue` style; empty states for each section ("No Sources have polled yet", "No Narratives yet", ...); usage shown as a bar with "$used of $budget" and "N of 10 Proposals today"; errors shown in full width red text with the time; no `<button>`, form, `$fetch` with a method other than GET, or `useStore` write anywhere on the page. A test asserts every `/api/activity/*` handler file is a `.get.ts` and that `activity.vue` contains no `@click`/`<form`.
- [x] **Client-only refresh.** The page fetches with `useFetch` (SSR renders real data) and refreshes with ONE `setInterval(refresh, 10_000)` created inside `onMounted` and cleared in `onBeforeUnmount`; the "x ago" clock is a `ref` updated by a timer created in the same `onMounted`, initialised to a fixed value on the server and set to `Date.now()` on mount (no `Date.now()` in the SSR render, to avoid a hydration mismatch). Nothing at setup scope calls `setInterval`/`setTimeout`. A test greps `activity.vue` to enforce no timer outside `onMounted`.
- [x] **verify:boot loads the page.** `pnpm verify:boot` gains a step that starts the War Room (built or `nuxt dev`, whichever the SSR-fix ticket established) against the seeded temp `ARGUS_DB`, requests `/activity`, and passes only on HTTP 200 with the four section headings in the SSR HTML and no `[nitro]`/`500` in the server output; the server is killed and no child survives (same process-group check as step 3).
- [x] `pnpm check` passes

**Notes:** keep the three routes under `server/api/activity/`. The polls table is written by the worker only; a War Room write path is out of scope. Source ids come from the Sources the worker builds (`packages/core/src/sources/`); do not duplicate that list in the War Room.
