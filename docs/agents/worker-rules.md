# Worker rules

Rules for agents that change this repo. Briefs point here.

- Change files only with the Edit and Write tools. Never patch files with python, sed, perl, or shell heredocs.
- One plain command per Bash call. No `&&`/`;` chains, no loops, no subshells.
- `git add` names each file. Never `git add -A` or `git add .`.
- If a safety check blocks a command, stop and report it. Never retry a variant.
- No writes to /tmp. Test temp files go through `packages/core/src/testing/temp.ts`; other scratch goes on the home disk.
- Never build a RegExp from a non-literal (`new RegExp(x)`, `RegExp(x)`): input that becomes a pattern is a ReDoS hole. `pnpm lint` rejects it (`argus/no-dynamic-regexp`, `config/oxlint/argus-plugin.js`; tests exempt). Use a regex literal or a linear matcher; reviewers reject any `oxlint-disable` of this rule that lacks a one-line reason.
- War Room links from stored or fetched data go through `safeHttpUrl` (`apps/warroom/app/utils/safe-link.ts`) or the `UrlLink` component. `pnpm lint` rejects a raw bound `:href` in a `.vue` template (`argus/no-raw-href`, `scripts/lint-links.mjs`; no disable comment, route the link instead).
- Browser boxes on a War Room page: run `pnpm page:check <path>` (headless, throwaway profile, 1240 and 390 px) and cite the screenshots and exit code. Never open or resize the user's Chrome or use the Argus Chrome profile for it. For keyboard boxes add `--keys "focus=<selector>,Enter,Escape" --watch <selector>` (fixed key list; Enter/Space activate the focused element, so pick focus/open/close targets only; the script aborts every non-GET/HEAD request and counts it as a failure, exit 1; to prove Enter on a button that POSTs, add `--expect-post <path>` (repeatable, `*` = one path segment, e.g. `/api/picks/*/withdraw`): that request is still never sent, is printed as `expected POST seen: <method> <path>` and does not fail, while a run where it never happens fails; any other non-GET still fails). For a page whose cards are empty on live data use `pnpm page:check --seed --all` (or `--seed <path>...`, `{tech}` `{metaMeme}` `{newsMeme}` `{hostile}` `{angle}` `{topicMeme}` stand for the sample Proposal ids) and say in the box that the run was seeded; never hand-seed a `.backup` copy of the live DB. Each run writes to its own fresh folder `$TMPDIR/page-check/run-XXXXXX` (the newest 10 are kept) and prints `output folder: <dir>` last, also when it fails; cite that path. A `--seed` run without `--port` takes a free port from the OS, so parallel runs do not collide; a plain run checks the War Room on 3100 unless you give `--port`. Do not pass a fixed `--out` or `--port` in parallel runs.
- A worktree under `.claude/worktrees/` with no `node_modules`: run `pnpm wt:setup` first (offline install; a hook tries it at start, and it is a no-op elsewhere). Do not run a bare `pnpm install`.
- Kill processes by PID only, never by name pattern.
- Stop, start and inspect the live War Room and worker only with `pnpm dev:stop`, `pnpm dev:start`, `pnpm dev:status` (`scripts/dev-server.mjs`, which wraps both in `systemd-inhibit`). Never start or kill those processes by hand. `dev:start` also reads `ARGUS_*` keys and the one exact name `HELIUS_API_KEY` (only those) from the repo-root `.env` into both processes; a variable already set in the shell wins, and the start prints one `env:` line with the key names taken and overridden.
- While iterating, run `pnpm test:fast` (or `pnpm check:fast`) or just the test files you touch. The fast tier skips the slow tier (~1-2 min instead of ~9); it never stamps.
- Commit first, then run the full `pnpm check` once on the clean tree: it stamps only a clean worktree (a dirty start prints "not stamped"). On failure fix, `git commit --amend` (or a follow-up commit) and re-check; never run it after every edit. At most two full suites run on this machine at once, enforced by the next rule.
- `pnpm check` takes one of two machine-wide test slots itself and waits (printing "waiting for a test slot") when both are taken; `node scripts/test-slot.mjs status` shows who holds them. Never count processes with `pgrep`.
- A new test that spawns real processes (wrangler, podman, the worker, a real server) or takes over ~10 s goes in the slow tier: add its path to `SLOW_TESTS` in `vitest.tiers.mjs`. `scripts/test-tiers.test.ts` guards that every test file is in exactly one tier.
- Signal tests target the node process (or its process group), never the pnpm wrapper, which does not forward signals.
- Your shell's cwd does not persist between calls; name the worktree in every command (`pnpm --dir <wt>`, `git -C <wt>`).
- A PreToolUse hook (`.claude/hooks/bash-guard.sh`) enforces two of these rules: it denies in-place `sed -i` and `cd <dir>` chained with `&&` or `;`.
- Before you report, stop every background task you started (test runs, `pnpm check`, monitors, dev servers, loops). A finished worker must hold no test slot and leave no process running. A SubagentStop hook checks this; it will send you back to stop leftovers.
- `pnpm check` takes about 6 minutes alone and can pass the Bash tool's 10-minute foreground limit when other checks run, so run it with `run_in_background: true` and wait for its completion notification; do not report, and do not start another check, while it runs. Run other commands expected to take over 2 minutes with `timeout` set to 600000. Never start monitors, watchers, `tail -f` or `sleep`/`pgrep` loops to wait for a check.
- Tickets here are markdown files under `.scratch/<feature>/issues/`, not GitHub issues: never write `Closes #N` (or `Fixes #N`) in a commit message; name the ticket file or say "War Room ticket 19" instead. A `#N` keyword can close an unrelated GitHub issue or PR on push.
